## 2. 修复 `bootstrap` 事件的 `actor_id` 不一致（优先级：P1）

**文件**：`src/loop_controller/server.py`（[L642-L668](file:///c:/Users/26343/Desktop/loop-controller/src/loop_controller/server.py#L642-L668)）

当前 `anchor_bootstrap` 事件写死：

```python
actor_id="admin",
```

而其他 Admin 操作在 `_audit_admin_operation()` 中使用：

```python
actor_id = f"api-key:{hashlib.sha256(api_key.encode()).hexdigest()[:12]}"
```

这导致审计中无法追踪是哪位管理员执行的 bootstrap。

**修复要求**：
1. 新增一个私有方法（例如 `_admin_actor_id(request: Request) -> str`），从 `Authorization: Bearer <key>` 中提取实际 key，计算 `api-key:<sha12>` 作为 `actor_id`。
2. 在 `_audit_admin_operation()` 中也复用该方法，替换当前使用 `self._api_key` 的方案。
3. `_handle_admin_evidence_anchor_bootstrap()` 中构造 `AuditEvent` 时，使用新的 `_admin_actor_id(request)`。
4. 如果请求未提供 API key（配置为 None 时允许匿名访问），回退为 `actor_id="unauthenticated"`。

**注意**：不要暴露原始 key，只存 SHA256 前 12 位。

## 3. Anchor Service 显式 URL decode `stream_id`（优先级：P2）

**文件**：`examples/contrib/anchor/anchor_service.py`（[L254](file:///c:/Users/26343/Desktop/loop-controller/examples/contrib/anchor/anchor_service.py#L254)）

当前直接从 path 参数读取：

```python
stream_id = request.path_params["stream_id"]
```

若 stream_id 包含编码字符或前置代理未正确解码，可能误触发 `anchor_stream_mismatch`。

**修复要求**：
1. 在文件顶部导入 `urllib.parse`。
2. 修改为：

```python
stream_id = urllib.parse.unquote(request.path_params["stream_id"])
```
