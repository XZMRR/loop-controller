## 2. 安全回归（HMAC 审计链）

- [ ] `audit_hash_algo` 默认是 `hmac-sha256`
- [ ] `LOOP_CONTROLLER_AUDIT_HMAC_KEY` 缺失时启动 fail-closed
- [ ] key 小于 32 字节时启动 fail-closed
- [ ] hex/base64 非法时启动 fail-closed
- [ ] `LOOP_CONTROLLER_AUDIT_KEY_ID` 为空字符串时启动 fail-closed
- [ ] key 不出现在日志、异常、审计事件、测试输出中
- [ ] `key_id` 不出现在审计事件以外的位置（除配置与启动日志）
- [ ] event key 与 seal key 使用域分离
- [ ] 审计事件包含 `key_id` 且非空
- [ ] seal 记录包含 `key_id` 且非空
- [ ] 修改任一审计事件后验证失败
- [ ] 删除任一审计事件后验证失败
- [ ] 调整事件顺序后验证失败
- [ ] 截断文件后验证失败
- [ ] 伪造 seal 后验证失败
- [ ] 旧 `sha256` 文件可验证
- [ ] 混合算法文件被拒绝启动

---

## 3. 会话风险回归

- [ ] `runtime.create_task(...)` 自动创建或复用 session
- [ ] 30 分钟内同 `(user_id, agent_id)` 复用 session
- [ ] 超过 30 分钟创建新 session
- [ ] 手工构造的伪造 `session_id` fail-closed
- [ ] `session_id` 与 `user_id` 不匹配 fail-closed
- [ ] `session_id` 与 `agent_id` 不匹配 fail-closed
- [ ] deny、critical、approval_denied、approval_granted 加分正确
- [ ] low-risk success 减分正确
- [ ] score clamp 在 `[0, 1]`
- [ ] `recent_tags` 最多 10 条
- [ ] 低风险成功不会清掉 `recent_tags`
- [ ] 进程重启后 risk state 可通过 JSONL replay 恢复
- [ ] 最后一行损坏时忽略并记录 WARNING
- [ ] per-profile threshold 会进入 Rego input
- [ ] 高 session risk 下：
  - [ ] allow → require_approval
  - [ ] modify → require_approval
  - [ ] deny → deny

## 6. 发布步骤

在确认以上所有检查项后，在最终 HEAD 上执行：

```bash
git status
git log --oneline -5
pytest tests/ -q

# 以下命令在检查全部通过后执行
git add .
git commit -m "release: v0.2.0 trusted execution baseline"

git tag -a v0.2.0 <final-head> -m "v0.2.0: trusted execution baseline"
git push origin v0.2.0
```

注意：

- `<final-head>` 必须是包含 P0 修正、P1 L2、audit_key_id 与版本号更新的提交；
- **不要给旧 `d054fc8` 打 tag**；
- tag 推送后不可修改，务必确认全量测试与手动 gate 通过。
