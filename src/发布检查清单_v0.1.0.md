CI 的 e2e 使用 FakeGateway，以下步骤验证**真实 stdio MCP 转发**（发布前必跑）：

```bash

#      /data/kb 与 /data/output 已就绪，approval.yaml 中 send_email behavior=approve

# 1. 真实链路端到端（filesystem server + mock email server 均为真实 MCP 进程）
python examples/research_agent_example.py
# 预期：search → read → write 成功；send_email → require_approval → approve → execute
#      data/sent_emails.jsonl 有记录；data/audit.jsonl 事件链完整

# 2. 审批拒绝路径
#    改 approval.yaml behavior=deny 后重跑
# 预期：send_email → require_approval → deny → blocked

# 3. 审计链校验
python -c "from loop_controller.infra.audit_store import JsonlAuditStore; \
           assert JsonlAuditStore('data/audit.jsonl').verify_chain()"
```

## 附：四幕演示脚本（面向治理者 / 利益相关方）

> 目标：10 分钟内讲清"这个系统治住了什么"。每幕对应验收标准，演示前重置 `data/`。

**第一幕：正常工作流（A1）**
跑示例脚本。旁白："Agent 搜索、读内部知识库、写摘要——每个动作都经过策略判定后才执行。"

**第二幕：审批链路（A5）**
`send_email` 触发 require_approval。先 behavior=approve 演示放行；改配置 behavior=deny 重跑演示拦截。旁白："外发动作必须人类审批，审批人配置化、行为可审计。"

**第三幕：越权与组合风险（A3/A4/A9）**
演示三个拦截：读 `/data/kb` 之外的文件 → deny；发往外部邮箱 → deny；先读知识库再发外部邮件 → 组合规则 deny。旁白："单个合法的动作组合起来可能产生新风险，系统能识别。"

**第四幕：审计可信度（A12/A13）**
打开 audit.jsonl 展示掩码效果（密码/邮箱不可见、哈希链字段）；手动改中间一行，跑 `verify_chain()` 检出失败。旁白："审计日志本身防篡改、不泄露敏感信息——审计不会成为新的泄露源。"
